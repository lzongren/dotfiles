# v0.8 潜在用户初审：有条件接受有限真实试用计划

结论：**有条件接受计划，但尚未同意按当前未填实的安排入组，更不表示愿意付费。** 我愿意在真实兼容性、权限和费用准备通过后，用一条低风险的真实工作路径试七天。下面第 1–3 项是我入组前需要落实的条件；第 4 项是必须收紧的结论口径，第 5 项是小修。无需为了得到我的接受继续扩展功能或研究规模。

身份与证据：延续前轮同一模拟潜在用户，有几十个长 agent 会话，主要痛点是跨天恢复理由，不愿维护第二份知识库。这是模拟购买者/参与者判断，不是真人研究、产品需求验证或实际试用同意。已阅读 prfaq-content-v0.8.json 的全文段落、表格和 strategy-outline-v8.json。未读原型实现，也未重试浏览器。前轮背景以当前文档和本线程原始试用记录核对；记忆中的“不手工维护项目、自动化可纠正”仅作为偏好定位，不作为当前能力证据。

## 1. 入组条件：记录了研究负担，还没有限制研究负担

文本证据：FAQ 20–21 与“怎样得到可信的时间”要求自然 A/B、两条件练习、事件后短核验、每日一次可跳过补漏、全员第七天复盘；“阅读与核对”又要短问答核对请求归属、授权、未知。明确由研究者事后编码、不逐请求填表，是好的改进。但“短”“少量”没有上限，也未说明同一回访的这些核验是否合并。

我的判断：我可能是在替产品做七天标注，而不是恢复自己的工作。把问答时间单列并不能减少它。每次工作恢复后马上问我为什么这样做，还可能改变我下一次的核对行为。这个成本不会被统计纠正自动解决。

最小修改与可执行规则：

- 入组卡只列我实际要做的事情、次数和个人同意的总分钟上限；合并同一次事件的正确性/请求归属核验，不能分别追问。可将问题延至同一固定时段，无需打断每次恢复。
- 我个人愿意考虑的初始预算是一次接入与教学最多 30 分钟，首周额外研究问答/补漏/复盘合计最多 30 分钟；每日补漏不超过 2 分钟且可跳过。这是我的模拟偏好，不是通用研究标准。接入超过预算先停下，由我决定另约或退出。
- 到达上限后停止额外采集请求，已有缺失记未知，不让我补齐配额，不因跳过核验或退出减少固定报酬；原工具照常可用。研究者观察和事后编码不要求我陪同或重演。
- 主报告同时列产品成本与参与本研究的实际总投入；不能用“不计研究时间的净收益”为我辩护本周整体体验省心。

## 2. 入组条件：独立状态应是系统账本，而不是用户必须清掉的收件箱

文本证据：FAQ 6、15、18 和 inquiry_states 已承诺无需逐条关单/已读、历史折叠、收起不等于取消，且“关键未决范围仍会阻断相关修复”。但哪些问题影响当前决定由谁判定、普通未回答问题何时不再占“需要你”、收起后什么时候重新出现，还没有可操作规则。

我的判断：问题不消失是正确的，但“有未答复”不等于“现在需要我处理”。如果每一个不确定关联都要求我决定保留/忽略，等于把会话列表换成请求列表。任何未答复都能挡住修复，还会鼓励我为了通行而假装核实完成。

最小修改与可执行规则：

- 传输状态、是否需要用户行动、是否构成本次执行前提分别表达。普通等待默认归等待/历史，不增加“需要你”；单纯未回复不阻断已有明确授权的无关行动。
- 只有能展示“该未决项为何影响这次动作”的具体范围/依据时，才阻断相关动作；不能定位影响时标范围不确定并允许缩小本次动作、保存草稿或回原工具，不要求把整件工作全部关单。
- 收起仅改变展示，状态保留；没有新的相关回复、实质来源变化或用户主动重开，不反复弹回同一项。真正相关的新变化重新提示时说明变化，不要求重新配对、改名或维护编号。
- 准备期用隔离案例核对“一个相关未决项 + 若干无关待回复”的默认首页；真实周不强造问题。若我必须额外维护清单才能正确判断谁在等谁，这条路径记失败并收缩范围，而不是让我继续整理到指标好看。

这些是已有低维护承诺的具体化，不要求首发支持复杂任务管理或自动判断一切语义。

## 3. 入组条件：对本地查证的诚实表述已足够，但实际试用能力还必须选定

文本证据：FAQ 2、19 和 local_lookup_boundaries 很清楚地区分固定来源展示、针对问题检索、有出处解释，并承认当前原型只有固定汇总。没有命中与覆盖不足也分别说明。这回应了第八轮“未回答却报成功”的问题。问题在于真实首发能力仍写“能力清单据实填写”，一周试用也可能同时包含自动恢复、人工回原工具和仅展示记录。

我的判断：可以接受功能有限，不能到了第六天才发现我参与的是阅读器试用，而计划标题在验证“自动接上理由”。来源展示有价值，但它把答题成本留给我；这应是入组时就知道的取舍。

最小修改与可执行规则：

- 入组前为我的具体连接填写三档能力：展示记录 / 定位问题相关原段 / 有出处解释，逐项写支持与不支持、历史覆盖起点、失败后的入口；不只给一个“只读可用”徽标。
- 只有来源展示也可以邀请我试，但目标写成“恢复与来源定位/阅读负担”，不把问题已回答、自动恢复理由算作成功；同一研究中能力不同者分层报告，不以强能力用户替弱能力用户完成机制验证。
- 本地查询后保留未回答状态并直接给原记录/原工具入口，保留问题及草稿；不新增一次必须完成的“我已核实”确认。来源不足不要求用户补写第二份说明来让产品达标。
- 真实收费或自动执行仍遵守原准备条件；若只能人工复制，结果明确按人工路径计，不算自动原会话续接。

## 4. 结论口径修订：保守匹配不等于测量精确，也不能掩盖某几次明显增负

文本证据：FAQ 21 与 inquiry_trial_protocol 用 ΔR 对比匹配 A 的中位数、最小/最大值，保守端不大于 0 才记“未增加”。R 不重复计入 E，M 没发生不记零；总收益改善也不宣称 R/M 均改善。这些规则合理且比只报总数强。缺口是：主动阅读时间靠最小时间戳、少量观察与事后编码，匹配敏感性没有覆盖编码不确定性；“这些已观测事件”也未明确指逐事件还是个人汇总。

研究方法判断：两个 A 不足以精确代表基线，但计划已承认不是因果估计，我不要求把探索变成统计研究。需要避免的是用几秒的负差作出很肯定的“未增加”，或平均收益遮住几次强迫重读。

最小规则：

- 主结果固定为每人同一匹配集合的汇总，同时列每个 B 的 R/Q/X/M 归属、增加方向、最大增负案例和缺失，不跨人合并成“未增加”。无需要求每一次都更快。
- 不能可靠拆分的时间保留区间/未知；“未增加”的保守判断同时考虑这类记录不确定性。方向被编码范围或单事件去除改变就说不确定，不必另造统计显著性阈值。
- 30% 和 30 分钟继续不是我的双硬门槛；我可以接受少量有用核对换来整体省心。但若重复整理/误报让我放弃使用，这个反例不能被总收益或付款抵消。
- 第七天可以得到“值得再观察/范围不适配/明显增负”的决定；不能证明长期免维护。原定缺机会才延长、无匹配不计算、不用演示样例补自然收益，均保留。

## 5. 小修：版本尾注与参与条款

规划 sources 章节仍有“本规划 v0.7”“配套 PRFAQ v0.7”“本轮依据 U8–U10”，末尾又追加 v0.8/U11–U13。应将旧内容标为历史或统一本轮说明，避免评审把不同版本当作同一已验证链路。

FAQ 7、13、22–23 的候选 19 美元、总报价、首购/退款/续费分开没有发现与前轮冲突；三份同人案例及其中两人自费是产品侧继续投入规则，不应变成参与者必须交出的作业。入组卡还应填明试用期许可是否收费、增量费用由谁承担、我的预算、结束时不默认转订阅、退出后连接/派生数据如何处理。已有条款要求提前说明，这里是落实，不是要求改变候选价格或退款规则。

## 接受条件的收束

我不要求在入组前证明自己一定获益，也不要求所有分项下降。要的是有限范围、有限额外负担、可以随时用原工具完成工作，而且产品知道自己没有回答什么。

将第 1–3 项落成明确规则、收紧第 4 项结论口径并填实个人入组卡后，我在模拟身份下愿意进入七天有限真实试用计划。真实工程准备仍须通过；这不是实际招募、授权连接、付款或真实用户接受。若下一版仅增加更多指标和检查表却不减少我的义务，我不会因此转为接受。
